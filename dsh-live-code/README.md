# dsh-live-code · 实时代码侧栏

模型**读 / 写 / 编辑**文件时，右侧栏自动打开一个标签页，显示那个文件的代码（带行号），
**变更行高亮**并自动**跳到变更处**。不用再去翻工具调用参数猜它改了什么。

```
┌ 实时代码 · client.js ──────────────────────────────────────┐
│  client.js          [编辑] 已完成            ☑ 跟随        │
│  &lt;DSH 安装目录&gt;\dsh-live-code\client.js                     │
├────────────────────────────────────────────────────────────┤
│   69 │ function entryFor(wire, callId) {                   │
│   70 │   if (callId === undefined) return undefined;       │
│   71 │   return (wire?.ops ?? []).find((row) =>            │  ← 变更区间：
│   72 │     row.op?.callId === callId);                     │     淡背景 + 左侧竖条
│   73 │ }                                                   │
│   74 │                                                     │
├────────────────────────────────────────────────────────────┤
│  变更行 71–88                                               │
└────────────────────────────────────────────────────────────┘
```

## 触发规则

| 工具 | 触发？ | 说明 |
| --- | --- | --- |
| `read` | ✅ | 显示读到的文件 |
| `write` | ✅ | 显示写入后的文件（首次写入整块算变更） |
| `edit` | ✅ | 显示编辑后的文件，高亮被改的行 |
| `grep` / `glob` | ❌ | 只是搜索，没有单一目标文件 |
| `pwsh` / `bash` | ❌ | 里面也可能改文件，但无法可靠判断目标文件（宁可不显示，也不显示错的） |

## 标签页与宽度（重点）

- **每个文件一个标签页**：同一文件再次被读/写/编辑时，**复用**它已有的标签页并更新内容，
  不会越开越多。一张标签页以资源地址 `dsh-resource://live-code/<文件路径>` 命名，
  所以**列表里显示的是文件名**（地址里就带着它，即使该操作早已过期也照样显示）。
- **不会改动你调好的侧栏宽度**：打开时只带本次参数（没有 `paneId` / `replaceTab` / `preferNewPane`），
  面板也**不申报自己需要多少空间**，因此不会触发分屏、也不会触发自动全屏。
  你把侧栏拖到最窄之后，后续操作只是"复用或新开一个标签页并切过去"，宽度不动。
- 例外：**窗口宽度 < 768px 时，DSH 自己会把右侧栏切成全屏**（自带行为，本插件无法绕过）。
- 正文只保留**最近几次**文件操作的正文。**操作过期又没新内容的标签页会自己关掉**，
  不占你的标签栏（关闭前显示"这个文件没有新的读写操作，正在关闭…"）。
- 刷新页面**不会**为历史操作弹一堆标签页（插件"上电先记账"，只对之后发生的新操作开标签页）。

## 高亮与自动跳转

- 变更区间由**宿主半**算出来：把这次编辑的 `new_string` 在文件正文里**逐行匹配**，
  得到精确的 `from–to` 行号（不靠猜）。
- **语法着色与官方一致**：用 harness 自带的 `useCodeHighlighter`（同一个 shiki 实例 + 同一套
  `--shiki-*` token 变量），逐行渲染 token；**底色用 `--dsw-alias-bg-document-preview`**，
  也就是你点文件名打开预览时的那个底色（`--shiki-background` 只存在于 shiki 自己生成的元素上，
  拿来刷容器会解析不到而回落成灰底）。拿不到高亮器时自动退化为纯文本。
- 变更行：**淡色背景 + 左侧 3px 竖条**；目标行号**加粗并上色**。
- 打开时自动滚到变更行（落在视口上方 1/3 处）。
- 头部有个 **☑ 跟随** 开关：**它是全局设定**——在任何标签页里改一次，其它标签页也跟着变，
  并记进 `localStorage`，重开浏览器依然生效。关掉后就不再抢你的滚动位置。

## 写入过程中的显示

工具**已发出、还没执行完**的那段窗口里，面板显示**即将写入的内容**（`write` 的 `content` /
`edit` 的 `new_string`）：状态标「写入中 / 编辑中」，整段内容按"新增"高亮，并跟着滚到最后一行；
内容是逐段显示出来的（约 40 帧显示完），让代码看着一行行长出来。
落盘完成后自动切换成磁盘上的真实正文，行号与变更区间以磁盘为准。

> **如实说明**：DSH 只把**完整**的工具参数交给界面（`StartedToolCall.argsRaw`；`preparing` 阶段的
> 类型注释明确写着 "arguments are not yet available to tool views"），所以**逐字流出是拿不到的**。
> 上面的"逐段显示"是对完整载荷的呈现效果，不是模型真实的打字节奏。

## 边界情况

| 情况 | 面板表现 |
| --- | --- |
| 图片 / 字体 / 压缩包 / 可执行文件 | 「这是二进制文件，不能按文本显示」 |
| 超过 2 MB | 「文件过大（约 N KB），未显示正文」 |
| 文件不存在（刚删掉或还没创建） | 「文件不存在：可能刚被删除，或还没创建」 |
| 路径不是普通文件（目录等） | 「这个路径不是普通文件」 |
| 单个文件超过 2000 行 | 只显示变更窗口附近的行，底部标注「N 行，只显示 50–849」 |
| 同时有多个标签页 | 每个标签页最多 800 行，避免整体变重 |
| 子会话日志里继承自父会话的事件 | 跳过（`inheritedEventCount` 之前的部分），不会误报父会话的操作 |

## 安装

把本目录放到任意位置，然后在 profile 里注册：

```bat
dsh plugin --profile web add "<本目录的绝对路径>"
```

- profile 里记的是一条软链（junction）：
  `~/.dsh/profiles/web/node_modules/@local/dsh-live-code` → 本目录。
  **移动本目录后必须重跑一次上面的 `add`**，否则软链指空。
- 新增 bundle **需要重启 `dsh web`**；之后改 `client.js` 只需刷新页面。
- 适配 DSH 0.2.1-rc.2；其它版本未测试。

## 实现

两半，都不修改 DSH 自带文件：

- **宿主半（`index.js`）**：注册一个 `sessionProjections` 单元 `liveCode`，折叠本会话的
  `tool/call` + `tool/result` 事件，只留 `read`/`write`/`edit` 三种操作（记 callId / 工具 / 路径 / 状态），
  最近 20 次操作进 state（**state 里不存文件内容**，否则会写进 checkpoint 缓存）；
  文件正文由插件侧缓存按需读取（3 秒 TTL），变更行由 `new_string` 定位；
  注意 `tool/call` 是在工具**执行前**提交的，那时读到的是改动前的内容（`write` 甚至还没创建文件），
  所以 `tool/result` 到达时会**作废该文件的这次读数**再重读，且 `ENOENT` 绝不进缓存；
  `wire.view` 发出最近 3 次操作，每条带正文、窗口范围和变更行号。
- **客户端半（`client.js`）**：注册一个 tab 类型（认领 `dsh-resource://live-code/**` 地址）、
  它的正文与标题槽位，外加一个渲染 `null` 的静默触发器；触发器读到投影里出现新操作时，
  按**文件路径**打开对应资源地址——同一路径即同一地址，因此天然"一个文件一个标签页"。

用到的都是 DSH 官方接口：

| 接口 | 用途 |
| --- | --- |
| `ctx.sidebarRightTabs.register({ id, kind, patterns, title })` | 声明一种标签页类型，并用 `patterns` 认领自己的资源地址 |
| `ctx.sidebarRight.openResource(address, { params })` | 打开/复用一个文件的标签页（地址=文件，故不会重复开） |
| 槽位 `sidebar.right.pane.tab`（`key` = 类型 id） | 标签页正文 |
| 槽位 `sidebar.right.pane.tab.title`（同上） | 标签页标题（显示文件名） |
| `useTabInfo()` | 让每个标签页读到自己的地址与 `params` |
| `useProjection('liveCode')` | 读宿主送来的操作与正文 |
| `useCodeHighlighter` + `languageForPath`（primitives） | 官方语法着色 |

## 已知限制 / 不在范围内

1. **不提供"整文件"按钮**：想看整个文件时，直接用侧栏自带的「文件」标签页点开即可（自带预览），
   本插件不重复实现。
2. 只看最近几次操作，不做历史回溯。
3. 不解析 `pwsh` 里的文件改写，不做完整 git diff。
4. 逐字流式拿不到（见上文说明），只能对完整载荷做逐段呈现。

## 排查

| 现象 | 怎么办 |
| --- | --- |
| 操作文件时侧栏毫无反应 | 确认已重启 `dsh web`；用 `dsh plugin --profile web list` 看插件是否装上 |
| 标签页开了但没正文 | 看头部与底部说明（二进制 / 过大 / 不存在 / 只显示某一段） |
| 宽度还是变了 | 检查窗口是否 < 768px（DSH 自带的全屏规则），或是否有别的插件抢了标签页 |
| 标签页标题显示"实时代码"而不是文件名 | 该操作已经掉出最近 3 次，正文也不再保留（属预期） |
